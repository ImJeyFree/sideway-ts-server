# 변경 기록

## 2026-09-16 — 공개 서버와 비공개 튜너 코어 분리

### 목적과 구성

Windows USB TV 튜너의 방송을 PC와 Android에서 시청할 수 있도록 HTTP·UDP 송출, 채널 관리, 장치 제어 경계를 정리했습니다. 공개 서버는 Apache-2.0으로 제공하며, 실제 튜너 구현은 별도 바이너리 조건을 적용하는 DLL로 분리했습니다.

### 공개 서버 변경

- `src/main.cpp`, `src/TrayApp.cpp`: 중복 실행 방지, UTF-8 콘솔 출력, 실행 옵션, 트레이와 정상 종료 흐름을 구성했습니다.
- `src/HttpStreamer.cpp`: 대시보드·상태·채널·스캔 API 및 TS 스트리밍을 제공합니다. TCP 부분 전송을 처리하고, 실제 TS가 없으면 오류를 반환하며, 종료 시 클라이언트 작업이 끝날 때까지 기다립니다.
- `src/UdpStreamer.cpp`: 188바이트 TS 7개를 1316바이트 UDP 데이터그램으로 전달합니다. 송신 인터페이스 지정, TTL과 루프백, 전송 실패 처리를 포함합니다.
- `src/TsBroadcaster.cpp`: 시청자별 독립 버퍼를 사용합니다. 패킷 경계를 보존하면서 오래된 데이터를 폐기하며, 느린 클라이언트로 인한 지연 누적을 줄입니다.
- `src/ChannelStore.cpp`: 방송 목록과 마지막 선택을 JSON으로 저장합니다. 항목 검증·중복 제거·손상 파일 보관·임시 파일 교체를 적용했습니다.
- `src/TunerClient.cpp`, `include/ScanClient.h`, `sdk/TunerCoreApi.h`: 장치 제어를 C ABI로 위임합니다. DLL 위치와 API 버전을 확인하고, 콜백 데이터를 복사하며, 상태 문자열은 호출자가 제공한 버퍼로 받습니다.
- `include/WebDashboard.h`: 채널 선택·방송 시작/종료·스캔 시작/취소·진행 상태와 송출 상태를 제공합니다.

### 채널 검색과 재생 동작

- 채널 JSON이 없거나 비어 있으면 자동 스캔하며 `--scan`, `--no-scan`, `--channels` 옵션을 제공합니다.
- 웹에서 케이블/안테나, 8VSB/QAM256, 검색 범위를 선택할 수 있습니다. 케이블 연결 여부와 변조 방식은 별도 설정입니다.
- 취소·빈 검색 결과는 기존 목록을 덮어쓰지 않으며 부분 검색은 범위 밖 방송을 보존합니다.
- 스캔 중에는 시청이 중단되고 완료·취소 후 방송 복귀를 시도합니다. 튜너 한 개의 선택 방송은 모든 시청자에게 공통으로 적용됩니다.
- Android VLC 3.7.1에서 관측된 메타데이터 처리 충돌을 피하도록 코어가 선택 방송 송출에서 PSIP를 제외합니다. 웹 채널명은 유지하지만 플레이어에 원본 PSIP 편성 정보가 전달되지 않는 제약이 있습니다.

### 공개 범위와 배포

- 공개 대상은 서버 전송·UI·JSON·DLL 어댑터·SDK 헤더·모의 테스트·빌드 및 배포 도구입니다.
- BDA 구현, 방송 테이블 파서, 장치별 호환성, 내부 진단 코드는 공개 저장소에 포함하지 않습니다.
- 실제 채널 JSON, 수신 TS, 로그, 개인 환경, 인증 파일, DLL/LIB/PDB 및 빌드 산출물도 Git 공개 대상에서 제외합니다.
- Apache-2.0, 별도 바이너리 배포 조건, nlohmann/json MIT 고지를 추가했습니다.
- 배포 도구는 허용 목록으로 소스·실행·SDK 패키지와 SHA256 목록을 생성합니다. 이번 Git push에는 바이너리 릴리스 업로드를 포함하지 않습니다.

### 주석 보강

공개·비공개 소스 15개 파일에 한국어 주석 38개 블록을 추가했습니다. 버퍼 소유권, API 경계, 종료 순서, 패킷 정렬, JSON 보존 및 호환성 처리 이유를 설명합니다. 주석 추가 작업에서는 기존 실행 코드가 바이트 단위로 유지됨을 확인했습니다. 비공개 구현의 설명은 비공개 저장소에만 보관합니다.

### 검증 기록

- 주석 변경 후 공개 회귀 테스트 4개와 비공개 회귀 테스트 1개 통과.
- 비공개 DLL Release 빌드 및 장치 미사용 ABI 검사 통과: API 버전, 버퍼 크기, 잘못된 JSON·명령, 핸들 종료.
- push 전 SDK 없는 별도 빌드 디렉터리에서 공개 서버 전체 Release 빌드 성공 및 CTest 4개 통과를 확인했습니다. 배포 PowerShell 구문 검사와 staged 공백 검사도 통과했습니다.
- 이전 실기기 검증에서 PC 재생, Android HTTP 영상·음성 및 앱 종료 문제 개선을 확인했습니다. 이번 push 검증은 실기기 재생을 다시 수행한 결과가 아닙니다.

### 남은 제약과 후속 확인

유선 PC의 UDP 재생은 확인했으나 현재 시험 공유기의 Wi-Fi에서는 UDP 멀티캐스트를 사용할 수 없는 것으로 정리했습니다. 같은 PC도 유선에서는 성공하고 Wi-Fi에서는 실패했으며 Android 멀티캐스트 잠금 비교만으로 해결되지 않았습니다. 공유기 내부의 정확한 원인은 확정하지 않았습니다. 현재 Wi-Fi 시청은 HTTP를 사용하고 일반 공유기로 추후 UDP를 재검증합니다.

서버에는 사용자 인증이 없으므로 신뢰할 수 있는 내부망에서 사용합니다. SDK 없이 공개 코드의 빌드·모의 테스트는 가능하지만 실제 방송 수신에는 별도 코어 DLL이 필요합니다.
